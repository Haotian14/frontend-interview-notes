# Vue 3 响应式与依赖追踪

## 一句话结论

Vue 3 通过 `Proxy` 或 ref 访问器把“读取属性”变成依赖收集，把“修改属性”变成更新通知；真正重要的不是记 API，而是知道哪些操作仍会经过这条访问路径。

## 前置知识

建议先理解 JavaScript 的对象引用与访问器。响应式不是复制数据，而是在原始对象外面增加一层代理；原对象、代理对象和从代理里解构出来的普通值具有不同身份。

## 核心机制

### track 与 trigger

可以把核心模型简化为：

```js
let activeEffect
const bucket = new WeakMap()

function track(target, key) {
  if (!activeEffect) return
  let depsMap = bucket.get(target)
  if (!depsMap) bucket.set(target, depsMap = new Map())
  let effects = depsMap.get(key)
  if (!effects) depsMap.set(key, effects = new Set())
  effects.add(activeEffect)
}

function trigger(target, key) {
  bucket.get(target)?.get(key)?.forEach(effect => effect.scheduler(effect))
}
```

组件渲染、`computed`、`watchEffect` 都建立在 effect 上。effect 执行时读取 `state.count`，代理的 `get` 调用 `track`；之后 `state.count++` 经过 `set`，`trigger` 找到真正依赖这个属性的 effect。Vue 不是“对象一变就重渲染所有组件”，而是按访问到的属性建立依赖。

`WeakMap` 让目标对象没有其它引用时可以被回收；第二层 `Map` 按属性区分；`Set` 负责去重订阅者。真实实现还要处理分支切换后的旧依赖清理、嵌套 effect、数组长度、集合类型和调度顺序。

### ref 与 reactive

`reactive` 适合结构稳定的对象，返回的是代理：

```js
const form = reactive({ name: '', role: 'viewer' })
form.name = 'Ada'
```

`ref` 用 `.value` 的 getter/setter 包装一个槽位，既能装基本类型，也能整体替换对象：

```js
const selected = ref(null)
selected.value = { id: 42 }
```

在模板里 ref 会自动解包；在 JavaScript 里保留 `.value`，让读取与写入的边界明确。团队不必追求“全 ref”或“全 reactive”，选择应跟随状态语义：会整体替换用 ref，一组稳定字段可用 reactive。

### 为什么解构会断开

```js
const state = reactive({ count: 0 })
let { count } = state

count++       // 修改普通局部变量，没有经过 Proxy
state.count++ // 经过 Proxy，能够 trigger
```

丢失的不是对象内部某种神秘标记，而是“访问代理属性”这条路径。需要把属性作为 ref 传递时使用 `toRef(state, 'count')` 或 `toRefs(state)`；只读一次快照时直接解构没有问题。

同理，重新赋值整个 reactive 变量会让后续代码指向新代理，但持有旧代理的消费者仍订阅旧对象。需要整体替换时更适合 `ref`。

### computed、watch 与 watchEffect

- `computed` 表达派生值。依赖未变化时复用缓存，变化后先标记为脏，下一次读取才重新求值。
- `watch` 明确指定数据源，能拿到新旧值，适合请求、日志、持久化等副作用。
- `watchEffect` 立即执行并自动追踪同步执行阶段读到的依赖，适合依赖与逻辑天然写在一起的短副作用。

不要用 watch 把一个状态同步成另一个状态：能在渲染时计算的值应该是 computed，否则会出现两个真相源和额外更新。

## 项目应用

1. 表单对象可以用 `reactive`，选中项、当前文件、异步结果用 `ref` 表达可替换语义。
2. API 返回的超大不可变结构、编辑器实例、Canvas 对象用 `shallowRef`，只在整体替换时通知 Vue，避免递归代理无意义的内部字段。
3. 从 store 或 reactive 对象对外暴露属性时用 `toRefs` 或只读 computed，避免调用方一解构就失去更新。
4. 派生列表、价格、权限判断用 computed；请求和埋点用 watch，并通过清理函数取消过期工作。
5. 调试重复更新时使用 Vue Devtools 或 `onRenderTracked`、`onRenderTriggered`，确认组件实际追踪了哪个属性。

## 边界与反例

“ref 性能一定比 reactive 好”没有意义。大多数页面里差异远小于错误的组件边界和大列表渲染；应该先按可替换性和 API 易用性选择。

“解构 reactive 一定错误”也不准确。只读取一次快照、传给纯函数或用于日志完全合理；只有希望它继续与源状态联动时才需要 ref。

深层响应式不等于每次都深度遍历。Vue 在访问嵌套对象时按需返回代理；真正会主动遍历的是深度 watch 等场景，因此对大型数据要谨慎使用 `{ deep: true }`。

不要把类实例、DOM 节点、第三方编辑器实例深度 reactive 化。它们可能依赖自身身份或私有字段，应使用 `markRaw` 或 `shallowRef` 保存。

## 面试回答

Vue 3 的响应式可以概括成 track 和 trigger。`reactive` 用 Proxy 拦截属性读取和写入：effect 执行期间读取属性时，Vue 按目标对象和属性记录当前 effect；属性修改时再找到这组依赖，交给调度器更新。依赖关系可以理解成 `WeakMap<target, Map<key, Set<effect>>>`。

`ref` 则通过 `.value` 的 getter/setter 包装一个槽位，既支持基本类型，也适合整体替换对象。`computed` 是带缓存和脏标记的 effect，依赖变化只让它失效，下一次读取才重新求值。

常见边界是直接解构 `reactive` 属性后，局部变量的读写不再经过代理，所以无法继续追踪；整体替换 reactive 对象也会让旧引用断开。我通常用 ref 表达可替换状态，用 reactive 管结构稳定的一组字段，大型不可变对象或第三方实例用 shallowRef，派生值优先 computed，副作用才使用 watch。

## 深度追问

1. **为什么依赖表外层适合 WeakMap？** 它不会因为响应式系统持有键而阻止原始对象回收；目标对象不可达时，其依赖记录可以随之释放。
2. **computed 为什么能够缓存？** 它拥有自己的 effect 和脏标记。依赖变化时调度器只把它标为脏并通知消费者，真正读取 `.value` 时才重新执行 getter。
3. **为什么 reactive 解构会断开？** 解构得到的是当时属性值，之后访问局部变量不再触发代理的 get/set。`toRef` 保存的是指向源属性的访问器，因此仍能连接依赖系统。
