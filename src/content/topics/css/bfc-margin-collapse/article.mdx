# BFC 与外边距折叠

## 一句话结论

块格式化上下文（BFC）是一块布局互不干扰的独立区域；外边距折叠、浮动不撑高、文字环绕这三个"怪现象"都发生在同一个 BFC 内部，建立新的 BFC 就是把它们隔开。

## 前置知识

请先阅读[Flexbox 与 Grid 布局模型](/topics/flex-grid-layout)，理解现代布局里容器与项目的关系。本文关注的是**普通流**——块级盒沿块轴依次堆叠的那套规则，它仍然是文章正文、富文本内容和大量存量代码的实际布局方式。

## 核心机制

### BFC 是什么

一个 BFC 是一块块级盒参与布局的区域，规则有三条实用推论：

1. 内部的块级盒沿块轴依次排列，垂直外边距在**同一个 BFC 内**才可能折叠。
2. BFC 的高度计算**包含浮动子元素**，因此浮动不会"漏出去"。
3. BFC 的边框盒不会与外部浮动元素重叠，因此不会被浮动侵入。

根元素本身建立一个 BFC。其余常见创建方式见速查表，其中 `display: flow-root` 是唯一为此目的设计、且没有副作用的写法。

### 外边距折叠的三种情况

垂直方向相邻的外边距会合并成一个，取**较大者**（都为负时取绝对值较大者，一正一负则相加）。发生在三处：

```html
<!-- 1. 相邻兄弟 -->
<p style="margin-bottom: 24px">上一段</p>
<p style="margin-top: 16px">下一段</p>
<!-- 实际间距是 24px，不是 40px -->

<!-- 2. 父子之间（父元素没有边框、内边距、行内内容隔开） -->
<div class="parent">
  <p style="margin-top: 40px">子元素</p>
</div>
<!-- 40px 跑到了 .parent 外面，整个父元素下移 -->

<!-- 3. 空块自身的上下外边距 -->
<div style="margin-top: 20px; margin-bottom: 30px"></div>
<!-- 高度为 0、无边框无内边距时，自己的上下外边距折叠成 30px -->
```

阻断方式（按推荐顺序）：

- 让父元素建立 BFC：`display: flow-root`（针对父子折叠）。
- 在两者之间放入边框、内边距或行内内容。
- 改用 `gap` 表达间距——在 flex/grid 容器里根本不会发生折叠。
- 只写单方向外边距（例如统一使用 `margin-block-end`），从源头避免相邻两值竞争。

注意：**水平方向的外边距永远不折叠**，浮动元素和绝对定位元素也不与他人折叠。

### 浮动导致的高度塌陷

```html
<div class="media">
  <img class="media__thumb" src="/thumb.jpg" alt="" />
  <p>说明文字会环绕在缩略图右侧。</p>
</div>
```

```css
.media__thumb { float: left; margin-inline-end: 12px; }

/* 不做处理时 .media 高度不含浮动图，背景和边框会"塌"上去 */
.media { display: flow-root; }
```

历史上的解法是 clearfix 伪元素、`overflow: hidden` 或额外的清除元素。`overflow: hidden` 确实能创建 BFC，但代价是**任何超出的内容都会被裁剪**——阴影、下拉菜单、聚焦轮廓都可能被切掉，还可能意外产生滚动容器。`display: flow-root` 没有这些副作用，是今天的正确答案。

### 阻止浮动侵入

紧挨着浮动元素的普通块盒，边框盒会与浮动重叠，只有行盒被缩短——这就是文字环绕的实现方式。想要"右侧内容形成独立的一栏"而不是环绕，给它建立 BFC：

```css
.media__body { display: flow-root; }
```

不过在今天，这种两栏结构直接用 `display: flex` 或 Grid 表达更清晰，浮动应当回归它的本职：**图文环绕**和 `shape-outside` 之类的排版效果。

## 项目应用

1. 需要包住浮动或阻断父子折叠时，一律写 `display: flow-root`，不要再用 `overflow: hidden` 这种"顺带产生 BFC"的写法。
2. 组件间距统一用 `gap`，或者用"只设一个方向的外边距"约定（例如全站只用 `margin-block-end`），从根本上避开折叠推理。
3. 富文本容器（文章正文、Markdown 渲染结果）是外边距折叠仍然活跃的地方：给容器加 `display: flow-root`，避免首段的 `margin-top` 顶出容器。
4. 遇到"莫名其妙多出/少了一块间距"，先在 DevTools 里看被折叠的两个外边距分别是多少，再决定是阻断折叠还是改用 `gap`。
5. 看到 `overflow: hidden` 时留个心眼：它可能是当年为了清除浮动加的，现在正在裁剪你想要展示的浮层。裁剪与层级是两个问题，参见[层叠上下文与 z-index](/topics/stacking-context)。

## 边界与反例

"BFC 能解决所有布局问题"是夸大。BFC 只影响**普通流**中的块级盒；flex 项目、grid 项目、绝对定位元素都不在这套规则里，给它们加 `overflow: hidden` 不会改变对齐结果。

"外边距折叠是浏览器的 bug"也不对——它是规范行为，目的是让连续段落之间保持一致的排版间距，而不是把每段的上下间距加在一起。

`display: flow-root` 创建 BFC，但**不创建层叠上下文**；反过来 `transform`、`opacity` 创建层叠上下文，也不必然创建 BFC。两套机制正交，不要互相推导。

`overflow: hidden` 之所以能清除浮动是因为它创建了 BFC，但它同时是裁剪指令；`overflow: auto` 还可能带来滚动条与滚动锚定行为。把它们当作"清浮动技巧"是把副作用当作功能。

最后，`margin: auto` 在普通流里只能水平居中且需要确定宽度；垂直居中在普通流中不存在，需要 flex 或 grid。

## 面试回答

BFC 是块级盒参与布局的一块独立区域，它内部的布局不会影响外部，也不受外部浮动侵入。它解释了三个经典现象：

第一，外边距折叠只发生在同一个 BFC 内的普通流块级盒之间，所以相邻兄弟、父子之间、以及空块自身的垂直外边距会合并成较大的那个；第二，浮动子元素不撑开父高度，因为浮动脱离普通流，而建立 BFC 的父元素在计算高度时必须包含浮动；第三，紧挨浮动的块盒会被侵入形成文字环绕，建立 BFC 后就变成独立一栏。

创建方式我首选 `display: flow-root`，它是专门为此设计、没有副作用的；`overflow: hidden` 虽然常见，但代价是裁剪内容并可能产生滚动容器。补充一点：flex 和 grid 项目本身就建立独立的格式化上下文，所以现代布局里外边距折叠和清除浮动这两类问题基本消失了，用 `gap` 表达间距比用 `margin` 更可预测；BFC 的知识主要还是用来读懂富文本正文和存量代码。

## 深度追问

1. **折叠发生在哪几种情况，怎么阻断？** 相邻兄弟的上下外边距、父子之间没有分隔物时的外边距、以及高度为零的空块自身的上下外边距。阻断办法是让父元素建立 BFC、在中间加入边框或内边距、或改用 `gap`。水平外边距、浮动元素、绝对定位元素不参与折叠。
2. **`overflow: hidden` 为什么能清除浮动？副作用是什么？** 它使元素建立 BFC，而 BFC 的高度必须包含内部浮动。副作用是超出部分被裁剪（阴影、浮层、焦点轮廓可能被切掉），`auto` 还会引入滚动容器；`display: flow-root` 能达到同样目的且无副作用。
3. **为什么 flex 容器里没有外边距折叠？** 折叠是普通流的规则，而 flex 容器建立的是 flex 格式化上下文，其子项按 flex 算法定位，不参与块轴的普通流堆叠，因此没有可折叠的相邻外边距。
