# 前端复习手册 V2 设计规范

## 1. 目标

将当前以卡片摘要为主的单页应用升级为一套可长期维护、可系统阅读、可独立分享专题页面的前端知识手册。

V2 的首要目标是知识完整性和阅读深度。面试题库、代码示例和交互演示用于帮助理解和表达，不引入每日任务、学习打卡、积分、收藏或持久化进度。

## 2. 目标读者

手册采用基础到进阶的分层结构，同时服务三类读者：

- 初学者按章节顺序建立完整知识体系。
- 校招及初级工程师通过高频标记、面试回答和手写题集中复习。
- 有经验的工程师通过知识地图、关键词搜索和关联专题快速查漏补缺。

专题难度只使用 `基础`、`高频`、`进阶` 三种标签。标签描述阅读定位，不作为学习进度或能力评分。

## 3. 产品原则

1. 内容优先：视觉和交互必须帮助阅读、理解或检索。
2. 结论先行：专题首先回答“它是什么、解决什么问题”，再展开机制。
3. 机制可验证：关键结论应通过代码、流程图、对比表或浏览器行为验证。
4. 显式边界：说明适用场景、失败条件、常见误区和替代方案。
5. 内容可维护：每个专题独立存放，元数据通过统一类型和自动检查约束。
6. 无学习负担：不保存用户进度，不使用打卡、红点或连续学习提醒。

## 4. 内容架构

V2 最终包含 10 个章节、80 至 100 个专题：

1. HTML、语义化与可访问性
2. CSS 布局、渲染与工程化
3. JavaScript 语言核心
4. JavaScript 异步与 Web API
5. TypeScript 类型系统
6. React 原理与应用架构
7. 浏览器与网络
8. 性能、安全与稳定性
9. 构建、测试与工程体系
10. 手写题、项目设计与面试表达

每篇专题必须包含以下内容：

- 元数据：标题、章节、摘要、难度、预计阅读时间、关键词。
- 一句话结论：不超过一段，直接回答定义和价值。
- 前置知识：链接到最多三个已有专题。
- 核心机制：使用分层标题解释完整过程。
- 验证材料：至少包含代码、流程图、对比表三者之一。
- 项目应用：说明真实工程中的使用方式和决策依据。
- 边界与反例：至少一个错误做法或不适用场景。
- 面试表达：一段可在约 90 秒内讲完的结构化回答。
- 深度追问：两至四个问题，并提供答案要点。
- 关联专题：同章节或跨章节的下一步阅读入口。
- 资料来源：优先链接到规范、MDN、语言或框架官方文档。

## 5. 信息架构与路由

站点使用真正的页面路由：

```text
/
├─ /handbook
├─ /handbook/:chapter
├─ /handbook/:chapter/:topic
├─ /knowledge-map
├─ /interview
├─ /code
├─ /reference
└─ /404
```

路由要求：

- 每个专题拥有稳定、可分享的 URL。
- 浏览器前进、后退和直接刷新保持正确页面。
- 无效章节或专题显示站内 404，并提供目录和搜索入口。
- 页面切换后把焦点移动到主标题，保留键盘用户上下文。
- Cloudflare Worker 对客户端路由回退到 `index.html`，但真实静态资源 404 不被错误回退。

## 6. 页面设计

### 6.1 首页

首页用于解释手册的用途和结构，不展示进度仪表盘。首屏包含定位说明、章节入口、全文搜索和推荐阅读路径。后续区域展示知识版图、使用方法、高频专题和六个交互实验入口。

### 6.2 章节页

章节页包含章节简介、学习目标、前置章节、专题分组和推荐顺序。基础、高频、进阶专题在同一章节内清晰分层，但不锁定阅读顺序。

### 6.3 专题页

桌面布局由左侧章节树、中间正文和右侧页内目录组成。正文最大阅读宽度为 760px。滚动时右侧目录高亮当前标题，文章底部展示关联专题和上下篇。

移动端隐藏固定侧栏，通过抽屉访问章节树；页内目录折叠到标题下方。所有交互目标至少 44px，正文在 200% 页面缩放下仍可阅读。

### 6.4 面试题库

题库按章节、难度和关键词过滤，支持随机抽题、90 秒计时、答案展开和连续追问。所有状态仅存在于当前页面会话，不写入浏览器存储。

### 6.5 代码手册

代码手册聚合包含实现示例的专题，支持语法高亮、复制、输入输出展示和打开完整解释。第一阶段不引入通用在线编辑器或远程代码执行服务。

### 6.6 速查表

速查表只保留适合快速检索的精简信息，例如 HTTP 状态码、缓存指令、复杂度、浏览器存储、React 状态选择和 TypeScript 工具类型。每个条目链接到相关专题。

## 7. 视觉语言

保留暖白、墨黑和荧光绿的编辑风格。V2 减少大面积装饰标题和重复卡片，建立清晰的长文阅读层级。

- 暖白用于阅读背景，墨黑用于导航和重点结论。
- 荧光绿只表示关键入口、当前状态和重点术语。
- 章节可以使用低饱和辅助色，但不改变品牌主色。
- 正文字体使用本地托管的中文无衬线字体；代码使用本地等宽字体。
- 流程图和知识关系使用 React/CSS 或可访问 HTML，不使用无法读取的装饰图片代替内容。
- 保留现有社交分享图的视觉方向，并在最终内容与标题稳定后压缩到 400KB 以下。

## 8. 交互演示

V2 规划六个教学实验，每个实验必须独立、可键盘操作，并在关闭 JavaScript 动画后仍能阅读静态解释：

1. Event Loop：逐步执行调用栈、微任务、任务和渲染阶段。
2. 原型链：选择对象并观察属性查找路径。
3. CSS 层叠上下文：调整定位和 z-index，显示上下文树。
4. 浏览器渲染流水线：展示解析、样式、布局、绘制和合成的依赖。
5. HTTP 缓存决策：根据请求与响应头展示缓存判断路径。
6. React 渲染快照：比较直接更新、函数式更新和批处理结果。

交互实验属于独立实施阶段。内容引擎和专题页面不依赖实验完成才能发布。

## 9. 技术架构

保留 Vite、React、TypeScript 和现有 Sites 托管结构。

### 9.1 页面与组件

- `src/app/`：路由、应用外壳、错误边界和页面入口。
- `src/features/search/`：搜索索引、命令面板和结果高亮。
- `src/features/interview/`：筛选、随机抽题、计时和追问。
- `src/features/labs/`：六个相互独立的交互实验。
- `src/components/content/`：代码块、提示框、对比表、资料链接和专题导航。
- `src/content/`：按章节存放 MDX 专题。
- `src/content/manifest.ts`：章节顺序、专题元数据和关联关系。
- `src/styles/`：设计令牌、基础样式、排版和组件样式。

### 9.2 内容加载

专题使用 MDX 编写，通过 Vite 的 `import.meta.glob` 按路由动态加载。每个专题导出统一元数据，构建时生成目录和搜索文档。

内容清单负责：

- 验证 slug 唯一性。
- 验证章节存在且顺序合法。
- 验证前置知识和关联专题链接存在。
- 生成上下篇导航。
- 为搜索提供标题、摘要、关键词和正文纯文本。

### 9.3 搜索

使用 Fuse.js 构建本地索引。字段权重顺序为标题、关键词、摘要、正文。搜索面板支持上下方向键、Enter 打开、Escape 关闭和结果关键词高亮。

### 9.4 代码高亮

使用 Shiki 在构建阶段生成代码高亮 HTML，避免在客户端加载完整语法解析器。代码块同时保留纯文本，支持复制和无样式降级。

### 9.5 数据状态

只保留导航、搜索、筛选、计时和实验控制等瞬时状态。不使用 localStorage、IndexedDB、Cookie 或服务端数据库保存学习信息。

## 10. 错误处理

- 顶层错误边界捕获页面渲染异常，提供返回首页和重新加载操作。
- 专题动态加载失败时展示专题名称、重试操作和目录入口。
- 搜索无结果时提供缩短关键词和浏览章节的建议。
- 复制 API 不可用时选中文本并显示手动复制提示。
- 无效关联链接在构建阶段直接导致检查失败。
- 交互实验遇到无效输入时在控件附近显示文字错误，不只改变颜色。

## 11. 可访问性

- 页面提供跳到正文链接。
- 搜索弹窗具有焦点锁定、初始焦点和关闭后的焦点恢复。
- 路由切换后更新文档标题并聚焦页面主标题。
- 所有控件具有可访问名称、可见焦点和键盘等价操作。
- 图表同时提供文字说明或数据表。
- 支持 `prefers-reduced-motion`，不使用强制滚动动画。
- 颜色对比达到 WCAG AA。

## 12. 性能要求

- 首屏 JavaScript gzip 后不超过 100KB，不计算按需加载的专题内容。
- 章节和实验按路由分包。
- 社交分享图压缩到 400KB 以下。
- 不依赖 Google Fonts 等运行时外部字体请求。
- 搜索索引在用户首次打开搜索或浏览器空闲时加载。
- 生产构建不包含未使用的旧内容数据和组件。

## 13. 测试策略

### 13.1 内容检查

- 元数据必填字段、slug 唯一性和章节合法性。
- 所有内部链接、前置知识和关联专题都能解析。
- 每篇专题包含结论、核心机制、项目应用、边界和资料来源。

### 13.2 单元与组件测试

使用 Vitest、React Testing Library 和 user-event 测试：

- 搜索权重、关键词高亮和键盘选择。
- 章节与专题导航生成。
- 题库筛选、随机抽题和计时器。
- 代码复制成功及降级行为。
- 错误边界和专题加载失败状态。

### 13.3 端到端测试

使用 Playwright 验证：

- 首页进入章节并打开专题。
- 直接访问专题 URL 和刷新。
- 浏览器前进、后退。
- 搜索并用键盘打开结果。
- 移动端打开章节抽屉。
- 面试题计时、展开答案和进入关联专题。

## 14. 实施分解

V2 拆成四个可独立验收的阶段，避免一次性扩写导致内容质量失控。

### 阶段一：内容与阅读基础设施

- 建立真实路由、应用外壳和错误页面。
- 建立 MDX 内容系统、清单和内容检查。
- 完成长文专题模板、章节页、搜索和本地字体。
- 将八篇代表性专题重写为质量样板，覆盖八个主要技术方向。
- 建立 Vitest、组件测试和基础 Playwright 流程。

阶段一完成后，站点必须可以独立发布，并作为后续内容的稳定模板。

### 阶段二：完整内容扩展

- 按 10 个章节扩展到 80 至 100 个专题。
- 每批完成一个章节，并通过内容检查和人工抽查。
- 完善知识关联、权威资料、手写题和速查表。

### 阶段三：教学实验与面试训练

- 依次实现六个独立实验。
- 完成随机抽题、计时、追问和代码输入输出展示。
- 为实验和题库补齐键盘及移动端测试。

### 阶段四：成品验收与发布

- 完成桌面、平板、手机和 200% 缩放验收。
- 检查无障碍、性能预算、资源压缩和错误页。
- 更新社交分享资源并发布最终版本。

## 15. 阶段一验收标准

1. 首页、目录、章节、专题、题库、代码、速查和 404 均有独立 URL。
2. 直接刷新任一专题不会返回托管 404。
3. 八篇样板专题全部符合统一内容结构。
4. 搜索支持标题、关键词和正文，并能完整使用键盘操作。
5. 旧的单文件 `data.ts` 内容不再作为页面数据源。
6. 不存在学习状态持久化代码。
7. 内容检查、单元测试、端到端冒烟测试、lint 和生产构建全部通过。
8. 首屏脚本、分享图和外部字体满足性能要求。

## 16. 非目标

V2 不包含账户、云同步、评论、社区、后台管理、AI 问答、远程代码执行、学习排名、付费功能或内容编辑器。这些能力不服务当前手册核心目标，不进入实施计划。
